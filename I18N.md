DuriCare uses **i18next + react-i18next** for Vietnamese (`vi`, the default) and English (`en`) in the frontend interface.

Use the language selector on the login page or desktop/mobile header. Switching updates the interface without reloading or clearing login state, alert filters, or chat history. The preference is saved as `duricare-language` in localStorage and synchronizes across tabs. Storage restrictions fall back to an in-memory preference. The document's `lang` attribute follows the selection.

Translations live in `src/i18n/locales/vi/translation.json` and `src/i18n/locales/en/translation.json`, keyed by their Vietnamese source text. `src/i18n/index.ts` initializes i18next with `initReactI18next`, Vietnamese fallback, and bundled resources. Key and namespace separators are disabled because the source keys contain punctuation. Unknown keys fall back to the original text.

New components can use the standard `const { t, i18n } = useTranslation()` from `react-i18next`. Resources use standard interpolation, for example `"Xem {0} cảnh báo": "View {{0}} alerts"`; render it with `t('Xem {0} cảnh báo', { 0: count, count })`. English plural variants use i18next's `_one` and `_other` suffixes. `useLanguage()` delegates to `useTranslation()` to keep existing components subscribed. The existing `t(source, values)` helper delegates translation, interpolation, and plural selection to i18next, preserving current component and utility calls. Keep error source strings in state and translate them when rendering so existing errors also switch languages.

Use `getLocale()` with Intl/date formatters. Relative timestamps use `Intl.RelativeTimeFormat` for localized units and singular/plural forms. The compatibility helper takes the count as its first parameter, except the zone/event summary, where it takes the second. Chart labels are formatted at render time, so changing languages does not refetch sensor readings.

Farm/zone names, care notes, stored alert text, and AI answers are original content and are preserved. The AI welcome and suggested questions translate with the interface; existing chat messages remain intact. Backend APIs, stored records, notification messages, and firmware are unchanged. The existing AI backend responds in the question's language; the selector does not translate historical AI output.

Validation:

- `npm run build`
- `npm run lint`
- `node scripts/verify-i18n.mjs` — local Vite + headless Chrome, with mocked APIs; no external data is modified. Checks login validation, persistence, desktop/mobile layouts, shared labels, alert filters/errors, zone care logs, chat state, and the not-found page. Saves the report and screenshots under `verification/i18n/`.

Library reference: [react-i18next quick start](https://react.i18next.com/guides/quick-start).
